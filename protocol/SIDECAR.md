# Local sidecar protocol (v1)

`qrk serve --model /path/to/model --port 7877 [--token SECRET]` binds **127.0.0.1 only**. Use `--stdio` instead of a TCP server to spawn a helper from any language. Recognition audio is never uploaded. The application ships `qrk` plus its platform ONNX Runtime library; no Python/Node installation is needed by an end user. The 88 MB model is supplied separately and verified.

One connection owns one session. Start, send mono PCM, then stop. A new start can follow a completed stop. Reset discards the active session. Replies follow [events.schema.json](events.schema.json). Word indices are zero-based, ayah-relative; ayah numbers are one-based.

```json
{"type":"start","target":{"surah":112},"format":"f32le","sample_rate":16000}
```

Other target forms: `{"surah":2,"from":255,"to":257}` for inclusive ayah ranges; `{"surah":1,"ayah":7,"from":4,"to":9}` for half-open word ranges. The fully tagged Rust form (`kind: surah|ayahs|words`) is also accepted.

Formats: little-endian Float32 `f32le` or signed PCM16 `s16le`. Rates: 16000, 44100 or 48000 Hz; the sidecar resamples. WebSocket audio is a **binary frame**, aligned to 2 or 4 bytes. Each frame is limited to 1 MiB. Prefer 100–300 ms chunks and await/observe replies rather than flooding. Stop: `{"type":"stop"}`. Reset: `{"type":"reset"}`. The final events precede a `type: summary` reply.

In stdio mode every command is a JSON line. Encode audio as `{"type":"audio","data":"<base64 PCM>"}`. Stdout contains JSON replies only; diagnostics go to stderr. Lines are limited to 1.5 MB. EOF discards an unfinished session; send stop and read the summary first.

Security: at most four concurrent WebSocket sessions. When `--token` is set, send `Authorization: Bearer SECRET` in the handshake. Without a token, remote browser Origins are rejected; native clients without Origin and local file contexts are allowed. Web pages should always use a token and an explicit application-controlled process. Tokens are not model/account credentials. Do not bind this helper to a public network or grant untrusted web content access to its stdin.

## Node WebSocket client

Run `npm install ws` in your client project. This example sends silence, so a retry and empty summary are expected; replace the PCM with microphone/file data.

```js
const WebSocket = require('ws');
const ws = new WebSocket('ws://127.0.0.1:7877');
ws.on('open', () => ws.send(JSON.stringify({
  type: 'start', target: {surah: 112}, format: 'f32le', sample_rate: 16000
})));
ws.on('message', data => {
  const event = JSON.parse(data.toString());
  console.log(event);
  if (event.type === 'state' && event.state === 'listening') {
    ws.send(Buffer.alloc(16000 * 4));
    ws.send(JSON.stringify({type: 'stop'}));
  }
  if (event.type === 'summary') ws.close();
});
ws.on('error', console.error);
```

The packaged Node binding also exposes `Sidecar`, with the same events, and a native `Recognizer` for apps that already have PCM.

## Python stdio client

No third-party Python dependency is required for this process boundary.

```python
import subprocess, json, base64
p = subprocess.Popen(['qrk', 'serve', '--stdio', '--model', '/path/to/model'],
                     stdin=subprocess.PIPE, stdout=subprocess.PIPE, text=True)
def send(value):
    p.stdin.write(json.dumps(value) + '\n'); p.stdin.flush()
send({'type':'start','target':{'surah':112},'format':'f32le','sample_rate':16000})
send({'type':'audio','data':base64.b64encode(bytes(16000*4)).decode()})
send({'type':'stop'})
for line in p.stdout:
    event = json.loads(line); print(event)
    if event['type'] == 'summary': break
p.stdin.close(); p.wait()
```

## C# stdio client

```csharp
using System;
using System.Diagnostics;
using System.Text.Json;
var p = Process.Start(new ProcessStartInfo("qrk") {
    Arguments = "serve --stdio --model \"/path/to/model\"",
    RedirectStandardInput = true, RedirectStandardOutput = true,
    UseShellExecute = false
})!;
p.StandardInput.WriteLine("{\"type\":\"start\",\"target\":{\"surah\":112}}");
p.StandardInput.WriteLine(JsonSerializer.Serialize(new {
    type="audio", data=Convert.ToBase64String(new byte[16000*4])
}));
p.StandardInput.WriteLine("{\"type\":\"stop\"}"); p.StandardInput.Flush();
while (p.StandardOutput.ReadLine() is string line) {
    Console.WriteLine(line);
    if (JsonDocument.Parse(line).RootElement.GetProperty("type").GetString()=="summary") break;
}
p.StandardInput.Close(); p.WaitForExit();
```

## C ABI

`core/qrk-ffi/include/qrk.h` is generated by cbindgen. Creation receives model directory, optional corpus path and optional config JSON. A handle owns a mutex-protected session. Feed callbacks run synchronously **after** the session lock is released; callback strings are borrowed only until return. `qrk_stop` allocates a summary JSON string (including final events); call `qrk_string_free`. Never free a handle while another thread is using it; free each handle/string once. `qrk_last_error()` is borrowed thread-local storage. The ABI does not transfer audio ownership.

## Open-set spotting (SDK 0.3.0)

Start without a target:

```json
{"type":"start","mode":"spot","format":"f32le","sample_rate":16000}
```

The existing audio/stop/reset commands and transport limits apply. `configuration` can supply `window_seconds` (6–12, default 8), `min_words` (at least 3), `min_seconds` (at least 1.5), `min_margin` (at least 0.035), `high_margin` (at least 0.20), `ambiguity_margin` and `max_candidates` (2–32, default 8). Quotation events carry `start_seconds`/`end_seconds` on this session's input clock; the summary adds `quotes`. Word ranges are zero-based and half-open. A pause longer than 1.2 seconds may separate successive ayahs into distinct quotes.

Model-free lookup works without starting audio or loading weights:

```json
{"type":"match_text","text":"الذين آمنوا"}
```

It returns `type:text_match, verified:false, ambiguous, candidates`. Ambiguous audio emits `quote_detected, verified:false, ambiguous:true`, confidence at most 0.5, null primary citation/text fields and explicit candidates. Only a non-ambiguous acoustically verified suggestion has a selected span. The host decides whether to insert it; a candidate must not silently replace ASR text. See [spotting semantics, integration and limits](../docs/SPOTTING.md). Tracking remains the default `start` mode; use independent sessions for the two modes.
