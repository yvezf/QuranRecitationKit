# Clean NVIDIA model-v2 — verified

**Decision: promote model-v2 for SDK v0.2.0.** [Successful export and four-platform run](https://github.com/yvezf/QuranRecitationKit/actions/runs/41363708288), source commit `55df545f938d0454eeaae2f29b625056d746311d`. Model-v1 stays separately available for older SDKs.

## What the original 2/12 meant

The old check compared greedy acoustic token strings on twelve pure sine waves, not twelve recitations. The 10 mismatches were differences in arbitrary text returned for non-speech; they were not 10 missed Qur'an passages. We retained the [original failure receipt](HISTORY-2026-11-01.md) and raw strings rather than relabeling them as equal. The corrected [validation contract](VALIDATION.md) tests whether the public recognizer rejects those sounds, plus direct source fidelity and real local recording behavior. Acceptance thresholds and expected-text rules did not change.

## Actual defects fixed

1. The static-int8 candidate used unrepresentative tone activation calibration and crashed ARM ONNX Runtime with a QLinearMatMul zero-point error. Replaced it with Microsoft ONNX Runtime dynamic int8 convolution and symmetric int4 constant MatMul, block 128; no calibration data.
2. The direct export showed up to 0.0403 log-probability error against NeMo. Intermediate outputs traced the discrepancy to preprocessing. NeMo's outer `forward` coerced the supposedly float64 input back to float32. Calling its existing `get_features` honors float64 accumulation, with unchanged float32 encoder/decoder. All 16 fixtures then passed the original 0.005 threshold; no tolerance increase.
3. Swift/.NET had independent hardcoded model-v1 cache paths. They now derive release/cache/manifest metadata from the native core. Default v2 has its own cache; previous SDK model-v1 bytes are not overwritten.
