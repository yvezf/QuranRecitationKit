# Clean model v2 candidate pipeline

This manually triggered pipeline starts with NVIDIA's checkpoint and uses the Apache-2.0 NeMo/PyTorch preprocessing path. It does not reuse Cyberistic's custom exporter. It exports raw-waveform inputs and both CTC/encoder outputs, then calibrates an int8 candidate using synthetic signals only. The v1 model, hash and default are unchanged.

**Status: exported and quantized on 2026-11-01, but synthetic decision parity failed. Not promoted.** See [the status receipt](STATUS-2026-11-01.md) and [workflow run](https://github.com/yvezf/QuranRecitationKit/actions/runs/41359583554). The SDK default remains model-v1. Int4 is deliberately gated: apply ORT MatMulNBits only when supported and after parity evaluation; static int8 plus dynamic int4 is not assumed to preserve decisions.

The source checkpoint is pinned by revision, size and SHA-256 in [source.json](source.json), fetched from NVIDIA's Hugging Face repository, and verified before NeMo restores it. The workflow uses matching CPU PyTorch wheels, NeMo-compatible NumPy/Arrow/datasets/PEFT pins and a compatible ONNX IR pin. `environment.txt`, `source.json`, `export.log`, candidate metadata and the parity report are retained in the workflow artifact. The artifact is an unvalidated candidate, not a model release. Neither Cyberistic's exporter nor its preprocessing code is used by this pipeline.

Run `export_clean.py --out <local-directory>`, then `check_parity.py --v1 <local-v1-model> --v2 <candidate-int8.onnx> --report <report.json>`. The workflow records exact installed dependencies. No reciter audio is used, fetched, or shipped. Synthetic decision parity does not establish real-recitation accuracy or authorize publication. Review the report, test owned/local recordings, update model metadata and compatibility deliberately, and publish under a separate `model-v2` tag only after approval.
